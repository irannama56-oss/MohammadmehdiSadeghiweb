# 2026-11-25 — Music search UI localized to English

User rule (stated firmly, second time): **no Persian may be visible on the site**.
Persian is allowed only where it exists for SEO — meta title/description/keywords,
JSON-LD, `<noscript>`, and `sr-only` blocks.

## Audit result
`src/**` Persian occurrences are all legitimate (SEO meta, JSON-LD, `sr-only`):
`Page/Project`, `Page/Contact`, `Page/About`, `Page/About/Bio/AboutMe`,
`Page/Blog`, `Page/Home`, `Page/Home/InformationText`, `Hooks/usePageSEO`.
The **only** visible Persian UI was in `Page/Home/MusicSearch/index.jsx`.

## Changes
- `MusicSearch/index.jsx`
  - `SUGGESTIONS` → English: "I feel down", "Party mode", "Gym workout",
    "Study focus", "Night drive", "Romantic". All resolve in the engine
    (verified: Party & Dance, Study & Focus, Night Drive, Loneliness).
  - "نتیجه‌ی جست‌وجوی مستقیم" → "Direct name search"
  - "نزدیک‌ترین آهنگ به حال‌وهوات: " → "Closest match to your vibe: "
  - "یه آهنگ دیگه با همین حس" → "Another song with the same vibe"
  - `matchReasonFa` → `matchReasonEn`
- `src/lib/moodEngine.js`
  - new `reasonForEn(intent, qm)` returning English reasons
    ("Matched mood: X", "Direct match on song or artist name",
    "Artist + mood: X", "Closest song to your input").
  - response now carries `matchReasonEn` next to `matchReasonFa` (Fa kept for
    backward compatibility / other consumers; nothing else reads it).
  - `empty` result object also carries `matchReasonEn: ""`.

## Notes
- `api/_mood-engine.js` is a one-line re-export of `src/lib/moodEngine.js` — no duplicate
  to patch. The engine runs server-side, so `matchReasonEn` does NOT appear in the
  client bundle (only the UI strings do).
- Verification: `npm run lint` clean · 23/23 mood golden tests pass ·
  `npm run build` ok · `dist/` contains the new English strings and zero old Persian ones.

## Standing rule
Any new UI copy must be English. Persian belongs in SEO surfaces only (`sr-only`,
meta, JSON-LD, `<noscript>`).
